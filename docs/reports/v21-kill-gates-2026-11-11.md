# V2.1 kill gates still in the code (2026-11-11)

These are found by a full read of `agy-lab/src/v21/` and `agy-lab/src/v21-*.ts`. Tests and the CLI-only `analyse.ts` are not included.
The token cap and the cut-off throw are **already removed** (commit `5618e32`, deployed 2026-11-11 08:53).

## A. Can stop a whole report (worst first)

| # | Where | What happens | Fix (record and label instead) |
|---|---|---|---|
| A1 | research.ts:428 | If no official site is confirmed, Step 1 stops: no Maps, reviews or outside pages. Step 2 skips and Step 3 refuses, so **there is no report**. Only 4 candidate domains are tried (research.ts:348). A short home page that says "protected by reCAPTCHA" counts as blocked (C2), which makes this gate fire more often. | Keep researching without a site, and label the report "official site not confirmed". |
| A2 | v21-step3-http.ts:115 | If the Step 3 LLM call fails, the **public report page shows 404**, even though the page is drawn from Step 2 items by code. | Serve the page from the Step 2 items, with code teasers and a note that the text was not written. |
| A3 | step3.ts:421 | If the subject is rejected (for example one unknown number such as "3 sources"), **the whole email is blanked** and Step 3 is marked failed. | Keep the email, use a code-written subject, and record the rejection. |
| A4 | v21-step2-http.ts:124 + v21-step3-http.ts:96 | A Step 2 run started without `rules:"v2"` gives a result that **Step 3 always refuses**. | Make v2 the default. |
| A5 | research.ts:598 | If the disk write fails, a **finished Step 1 is lost**: the database copy is saved only after the file write. | Save to the database first, and record a failed file write. |
| A6 | v21-step1-http.ts:76 | If writing the log row fails, Step 1 is marked failed and **the automatic Step 1.5 is skipped**. | Record the error and carry on. |

## B. Throws away a whole LLM answer

| # | Where | What happens | Fix |
|---|---|---|---|
| B1 | judge.ts:175 (parseAnswer), recheck.ts:154 | If the model writes "Here is the JSON:" before a valid object, **the whole answer is thrown away**. If every lane does this, Step 2 or Step 3 fails, and A2 follows. | Take the JSON object out of the text, and record that extra text was removed. |
| B2 | recheck.ts:140, step2-v2.ts:550 | If applying the checker's answer throws, its full text is not stored (`llm_raw: null`). | Store the text anyway. |

## C. Silently cuts data (no record)

| # | Where | What is lost |
|---|---|---|
| C1 | tidy.ts:265 | On a register page, only the first 6 name matches are kept, and they can all be generic words. **The real company entry can be cut, with no count shown.** |
| C2 | reader.ts:34-45 | A short real page containing "captcha", "cloudflare" and similar words is marked blocked and **cut to 500 chars**. A contact page loses its phone and address, and Step 2 is not told. |
| C3 | research.ts:321, 330 | A failed Brave or Tavily search looks the same as "no results". It is not recorded. |
| C4 | assets.ts:464 | Only the first 5 domains are audited. Email and brand domains are often cut. |
| C5 | assets.ts:545 | An **expired or invalid TLS certificate** never reaches Step 2; only "expires within 14 days" does. |
| C6 | assets.ts:688 | PageSpeed accessibility and best-practice flags are dropped; only SEO flags pass. |
| C7 | people.ts:113, 109, 93 | Step 1.6 reads only the first 3,000 chars of each page, so **footer phones and emails are missed**. Hits without the brand word are skipped, and own-site PDFs beyond 3 are skipped. None of this is recorded. |
| C8 | tidy.ts:344, 442 | Snippets are cut to 700 chars, reviews to 600 and owner replies to 400. The cut text can't be quoted. |
| C9 | research.ts:550 | A second probe on the same address is dropped with no entry. |
| C10 | step3.ts | The checked LLM summary is never shown on the report page. |

## Borderline: recorded, but a whole item is dropped for one bad part

- **step2-v2.ts:306 and 323:** one failed quote drops the whole finding, even when its other evidence passes.
- **check-findings.ts:49:** a short quote such as "4.8" always fails, which drops its finding.
- **step2-v2.ts:494 and 510, recheck.ts:84 and 91:** when the checker's fix fails, the original item, which had passed, is dropped.
- **step3.ts:246:** one unknown number drops the whole sentence.
